<!-- sdlc:auto:start overview -->
Notes A is a one-page notes app (add a short note, list notes, delete a note; no login, uploads or AI) generated by the Quorq AI SDLC platform as a monorepo with two applications. `frontend/` is a Vite 6 + React 19 SPA using react-router-dom 7, Tailwind CSS 4 and TypeScript. Per its README, its approved screens still render seeded sample data. `frontend/src/lib/api.ts` provides `apiFetch` and `API_BASE_URL` as the seam for wiring screens to real endpoints, but no screen uses it yet. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Pydantic 2. Its only real route is `GET /health`. No models or routers are implemented yet, and `StubResponse` is the placeholder shape for future generated routes. The database defaults to a local SQLite file (`sqlite:///./app.db`) and can be pointed at PostgreSQL 16, which `docker-compose.yml` provides, via `DATABASE_URL`. Tables are created on startup with `Base.metadata.create_all`. There are no migrations.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js and npm (a version supported by Vite 6)
- Python 3.12 (the version used by backend/Dockerfile) with pip
- Docker with Compose (optional: for the PostgreSQL 16 container or for building the backend image)
- Playwright Chromium browser (optional: installed via `npm run test:e2e:install` for e2e tests)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd backend
2. python3 -m venv .venv  # the Playwright config expects backend/.venv to exist
3. source .venv/bin/activate
4. pip install -r requirements.txt
5. uvicorn app.main:app --reload  # API on http://localhost:8000, using SQLite ./app.db by default
6. # in a second terminal, from the repo root:
7. cd frontend
8. npm install
9. npm run dev  # Vite dev server, by default http://localhost:5173 (an origin the backend's CORS allows by default)
10. # optional: use PostgreSQL instead of SQLite. From the repo root:
11. docker compose up -d db
12. export DATABASE_URL=postgresql+psycopg://app:app@localhost:5432/app  # credentials from docker-compose.yml; set before starting uvicorn
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend imports use the `@/` alias for `frontend/src`, configured in both vite.config.ts and tsconfig.json.
- TypeScript runs in `strict` mode, but `noImplicitAny` and `strictNullChecks` are disabled. Typechecking is a separate `npm run typecheck` step, not part of `build`.
- Vitest component tests sit beside the components they cover and match `src/**/*.{test,spec}.{ts,tsx}`, using jsdom and globals. Playwright specs live only in `e2e/`.
- Styling uses Tailwind CSS 4 via the @tailwindcss/vite plugin. Formatting uses Prettier, and linting uses ESLint 9 with typescript-eslint, react-hooks and react-refresh. The platform runs `npm run lint` as a gate during development.
- All HTTP calls should go through `apiFetch` in `src/lib/api.ts`. It prefixes `VITE_API_BASE_URL`, sends JSON, adds `Authorization: Bearer <VITE_API_SECRET_KEY>` when that value is set, and throws on non-2xx responses.
- Backend structure: one router module per architecture component under `app/routers/`. SQLAlchemy models go in `app/models.py` and inherit `app.database.Base`. Pydantic schemas go in `app/schemas.py`. Request-scoped DB sessions come from the `get_db` dependency.
- Unimplemented generated routes return a typed `StubResponse` instead of raising, so the OpenAPI document stays complete.
- The backend is configured through environment variables: `DATABASE_URL` and `ALLOWED_ORIGINS`. Tables are created from models at startup, and no Alembic migrations exist yet.
- Backend code is linted and formatted with Ruff (`ruff.toml`).

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `npm run test:e2e` fails to start the API server. | The Playwright webServer runs `../backend/.venv/bin/python -m uvicorn ...`. Create the venv inside `backend/` and install `requirements.txt` into it before running e2e tests, or set E2E_BASE_URL to test an already running app. |
| The browser blocks frontend calls to the API with a CORS error. | By default the backend only allows http://localhost:5173 and http://127.0.0.1:5173. If the frontend runs on another origin, start the backend with `ALLOWED_ORIGINS` set to a comma-separated list of origins. |
| The frontend calls the wrong API host. | `API_BASE_URL` comes from `VITE_API_BASE_URL` at build time, falling back to http://localhost:8000. Set it before `npm run dev` or `npm run build`. |
| The frontend fails to resolve `@/App`. | `src/main.tsx` imports `@/App`, and the frontend README describes `src/App.tsx` and `src/screens/`. Neither appears in this repository's file tree, so verify those files exist. If they are missing, they need to be restored or generated. |
| `npm run build` succeeds, but `npm run typecheck` reports errors. | This is expected: `vite build` does not typecheck. The README notes these errors usually come from untyped `useState({})` values read for named fields. Add types to those states. |
| Data written while using PostgreSQL is not there, or schema changes don't apply. | The backend uses SQLite `./app.db` unless `DATABASE_URL` is set. For the compose database, run `docker compose up -d db` and export `DATABASE_URL` before starting uvicorn. `create_all` only creates missing tables and does not alter existing ones, so there is no migration path yet. |
| Backend tests fail with `ModuleNotFoundError: app`. | Run `pytest` from the `backend/` directory so pytest.ini (`pythonpath = .`) is picked up. |
| Playwright's Chromium crashes inside a container. | The config already passes `--disable-dev-shm-usage`. Make sure the browser was installed with `npm run test:e2e:install`. |
<!-- sdlc:auto:end troubleshooting -->
